# BELIEF

> 정보를 흘려 사람들의 **믿음**을 바꾸고, 그 믿음이 만들어낸 행동으로 목표를 달성하는 턴제 전략 게임.

## 어떤 게임인가

당신은 도시에 정보를 흘리는 사람입니다. 직접 싸우거나 명령하지 않습니다.
할 수 있는 일은 **어떤 정보를, 어디에 퍼뜨릴지 고르는 것** 하나뿐입니다.

정보를 받은 NPC는 각자의 성향·기억·관계에 따라 그 정보를 **믿거나, 의심하거나, 확인하러 갑니다.**

**목표는 사람을 움직이는 것이 아니라, 사람이 스스로 움직이게 만드는 것입니다.**

---

## 플레이 방법

한 턴은 네 단계로 진행됩니다. 게임을 처음 시작하면 이 흐름을 안내하는 4단계 가이드가 나옵니다.

| 단계 | 하는 일 |
|---|---|
| **1. 정보 선택** | 손에 든 정보 카드 중 하나를 고릅니다 |
| **2. 장소 선택** | 그 정보를 퍼뜨릴 장소를 고릅니다 — 같은 정보라도 어디서 퍼지는지에 따라 설득력이 달라집니다 |
| **3. 정보원에게 전달** | 정보는 항상 정보원을 거쳐 유통됩니다. 전달하는 순간 확산이 확정됩니다 |
| **4. 관찰** | NPC들이 정보를 해석하고 행동합니다. 이동·조사·보고·감시 결과가 다음 턴의 판을 바꿉니다 |

각 미션에는 **턴 제한**이 있고(대체로 4턴), 제한 안에 목표 조건을 만족시키면 클리어입니다.
NPC의 현재 믿음 상태와 행동은 화면 우측의 **프로필 / 기록(Log)** 패널에서 확인할 수 있습니다.

### 진행 구조

**구역 1 → 구역 2 → 구역 3 → 대도시**, 총 **9개 미션**으로 구성되어 있습니다.
앞 구역에서 만든 상황은 뒤 구역으로 이어지지만, 각 미션은 그 미션 안에서 새로 달성해야 클리어됩니다.

## 핵심 시스템

### 믿음 상태 (Belief)

NPC는 각 정보에 대해 독립적인 믿음 상태를 가집니다. 이 상태가 그 NPC의 행동을 결정합니다.

```
Unknown → NeedsVerification → Doubtful / Plausible → Trusted
                                                   ↘ Denied
```

`Plausible` 이상이 되어야 NPC가 실제로 움직이기 시작합니다. `NeedsVerification`은 "확인이 필요하다"는
판단이라, 이 상태의 NPC는 정보를 확인하러 이동하거나 다른 인물에게 묻습니다.

### 설득력을 결정하는 세 축

같은 카드를 내도 결과가 달라집니다. 세 가지가 함께 계산되기 때문입니다.

- **정보 카드** — 내용 자체의 무게 (총 30종)
- **출처** — 시장 소문인지, 봉인된 편지인지, 항만 기록부인지 (총 18종)
- **장소** — 어디서 그 말이 나왔는지 (총 15곳)

여기에 NPC 개인의 **성향 태그**, **과거 기억**, **다른 인물과의 관계**가 더해집니다.

### NPC AI — 실제 LLM 판단

NPC의 판단은 하드코딩된 규칙표가 아니라 **실제 AI 모델 호출**로 이뤄집니다.
정보를 받은 NPC마다 성향·기억·관계·현재 상황을 담은 프롬프트가 만들어지고, 모델이
"이 정보를 믿을지, 어떻게 행동할지"를 판단합니다. 그래서 같은 카드를 내도 NPC마다 반응이 다릅니다.

**AI 호출이 실패해도 게임은 멈추지 않습니다.** 응답이 없거나 형식이 깨지면 그 판단 1회만
규칙 기반으로 대체되고 게임은 그대로 이어집니다.

API 키는 빌드에 들어 있지 않습니다. 브라우저에서 도는 웹 빌드가 키를 안전하게 가질 방법이 없으므로,
키를 아는 것은 중계 서버 하나뿐이고 게임은 그 서버로만 요청합니다
(→ [`Server/cloudflare-worker/`](Server/cloudflare-worker/)).

심사자가 별도로 설정할 것은 없습니다. 중계 서버는 이미 배포되어 있습니다.

## 프로젝트 구조

```
Assets/Belief/
├── Scripts/          C# 스크립트 196개
│   ├── Domain/         믿음·NPC 상태 등 순수 게임 규칙 (Unity 비의존)
│   ├── Systems/        확산·판정·진행 등 게임 시스템
│   ├── AI/             LLM 프롬프트 조립 · 응답 파싱 · 규칙 기반 폴백
│   ├── Presentation/   HUD, 월드 표현, 연출
│   ├── Data/           ScriptableObject 스키마
│   ├── Events/         시스템 간 이벤트 배선
│   ├── Bootstrap/      씬 진입점 · 의존성 주입
│   └── Debug/          자동 플레이스루 · 밸런스 측정 도구
├── Data/             기획 데이터 (ScriptableObject)
│   ├── Cards/ Sources/ Locations/     정보 30 · 출처 18 · 장소 15
│   ├── Npcs/                          NPC 17
│   ├── Missions/ Stages/              미션 9 · 구역 4
│   └── Memory/ Dialogues/ Actions/    기억 · 대사 · 행동
├── Scenes/           MainMenu · Zone1 · Zone2 · Zone3 · Metropolis
├── Art/ Audio/ UI/   아트 · 사운드 · UI 리소스
└── Docs/             기획서 · 밸런스 실험 기록 · AI 아키텍처 문서

Server/cloudflare-worker/    LLM 중계 서버 (API 키 보관 · 남용 방지)
```

핵심 게임 규칙(`Scripts/Domain`)은 Unity에 의존하지 않게 분리되어 있어, 에디터 없이도
자동 플레이스루로 밸런스를 반복 검증할 수 있습니다. `Docs/`의 밸런스 실험 기록이 그 결과입니다.

## 개발 환경 / 직접 빌드하기

- **Unity 6000.3.9f1**
- 렌더 파이프라인: URP 2D

```
1. Unity Hub에서 이 저장소를 프로젝트로 추가하고 위 버전으로 엽니다
2. Assets/Belief/Scenes/MainMenu.unity 를 열고 실행합니다
```

웹 빌드 및 배포는 Unity 메뉴 **Belief > Build > WebGL 빌드** 실행 후
루트의 `deploy-gh-pages.ps1` 을 돌리면 `gh-pages` 브랜치로 배포됩니다.

에디터에서 AI 호출 없이 돌려보려면 씬의 `GameInstaller` 에서 **Thinker Mode** 를 `RuleOnly` 로
두면 됩니다 (`FakeLlm` 은 네트워크 없이 LLM 경로 전체를 검증하는 모드입니다).
